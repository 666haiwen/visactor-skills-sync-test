# 透明素材：按宿主选择抠图能力

适用于穿搭全身与单品、人物肖像及辅图、旅行封面场景前景。先完成素材加工，再进入 HTML 排版；透明度检查脚本不是抠图工具。

## 豆包办公：直接使用 MediaKit

在豆包办公中，需要移除背景时，**首选并直接使用内置 MediaKit 技能**，不要先尝试本地分割模型、安装 rembg 或用其他生图工具重绘，失败后才转向 MediaKit。

1. 发现并读取宿主实际安装的 MediaKit 图片技能（通常为 `byted-mediakit-image`），以及其要求的 shared 依赖和去背景操作说明。依照当前工具合同执行，不假定存在 `call_skill()`，不硬编码未经确认的命令、参数或鉴权方式。
2. 输入本次任务的原图，明确要保留的主体。人物／穿搭保持身份、姿势、衣服、鞋包及原色；建筑／山体保留可辨识结构、枝叶和孔洞。目标是移除背景，不能重新设计主体或用图标替代真实照片。
3. 等待实际处理完成，将返回的透明结果保存为本地 PNG。若返回临时链接，先下载并确认文件可打开；不要把临时链接直接当最终 HTML 的素材地址。记录原图与结果映射、实际使用的工具和处理情况，不在交付中保存凭证或带密钥的临时 URL。
4. 用下述检查及目视验收确认结果，再内嵌到 HTML。用户已提供合格透明素材时直接检查复用，不重复抠图。

MediaKit 未安装、不可调用或处理失败时，明确说明素材缺口，保留原图和待补图的可编辑草稿；只有在宿主允许且确有可用替代能力时再尝试，并记录实际处理方式。不能把“文件已生成”当作抠图成功，也不能静默改用矩形原照、矢量山形、灯塔图标或占位人形交付为成品。

## 其他宿主

按当前可用的图像编辑／去背景能力处理；在提供 ImageGen 的宿主，遵循其图像编辑规则，以原图输入并请求透明背景。不要假设豆包 MediaKit 在其他宿主也可用。缺少处理能力时沿用上面的素材缺口处理方式。

## 共用验收

```bash
python scripts/inspect_cutout.py --image /绝对路径/cutout.png
```

- 结果需同时有可见主体和实际透明背景；全透明、全不透明、白底及烘焙棋盘格都不合格。alpha 通道存在不代表边缘正确。
- 在浅色、深色底上对照原图，检查发丝、衣物边缘、包带、手脚、建筑轮廓及内部孔洞；主体不能明显缺失、改色或变形。
- `inspect_cutout.py` 只检查透明度并提供候选色；`portrait_wrap.py` 只从既有 alpha 轮廓计算绕排区域。两者都不移除背景。
- 本地保存实际透明 PNG，成品 HTML 内嵌该文件。素材记录区分已完成的处理与待补项；模板中的 SVG 占位仅展示图槽，不能作为真实抠图结果。
